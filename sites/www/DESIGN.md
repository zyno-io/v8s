# Design System: v8s

## Overview

**Creative North Star: "The Review Desk, driven from the command bar"**

The v8s site is the PixelCI design system ("The Review Desk") carried over value for value, with v8s's identity swapped in. Every neutral, status triplet, radius, and shadow is PixelCI's, under the same token names that `siple-web` uses, so the sites read as one family. The marketing layer (display scale, generous sections, the faint desk grid and glow in the hero) is the PixelCI sales site's. v8s changes three things. The accent family is the app's indigo. The app's cluster connection dots (`--dot-*`) join as the live-state device. And the page is operated the way the app is: a working replica of the v8s interface sits in the hero, every feature section carries the real command that opens it as a Run chip, and `:` anywhere opens the replica's command bar.

The desk is quiet, dense, and utilitarian. A cool grey page; white cards with 1px hairlines and barely visible resting shadows; one indigo; status as small tags with a word in them. Collections are packed as rows inside one card rather than spread across airy feature cards. The only imagery is the app itself: the live replica, and real demo-mode screenshots in light and dark pairs. Nothing is illustrated, and no number is invented; performance figures appear only as labelled design budgets.

Light and dark come from one set of token names, redeclared for dark. Theme follows the OS through `prefers-color-scheme`; `html[data-theme]` pins the reader's choice from the header toggle. Components never branch on theme, with two exceptions: screenshot pairs show one of their two images, and indigo text (the Run chip label) uses Link Indigo, which is already themed.

**Key Characteristics:**

- PixelCI's Review Desk tokens unchanged, except the accent family (indigo) and the added `--dot-*` connection dots.
- One indigo for action, selection, and focus. In dark it is a brighter indigo that still carries white text.
- Status is a tag triplet with a word in it. Live connection state is a small round dot, always beside a word.
- Inter for people's words; monospace for machine text: commands, problem class names, file names, config.
- The page is driven by commands: a Run chip per demo-able section, a `:` command button in the header, and the hero replica answering them.
- Collections are one hairline card with divided rows or columns, at the app's density.
- No eyebrow labels. A heading stands alone; small caps appear only as the header of the list they sit on.

## Colors

PixelCI's cool near-neutral greys carry everything. One indigo family marks action, selection, and focus. Status tones appear only as tag, diff, and notice triplets, and four dot colours mark connection state. Every token has a dark twin under the same name (frontmatter suffix `-dark`). Values are in the frontmatter; the roles below are the ones that differ from PixelCI or are specific to this site.

### Primary

- **v8s Indigo** (`accent`): the logo tile's indigo. Fills the primary button (header Download, the hero's xl "Download for macOS", the 404's home button, the replica's Apply), the replica's command-bar prefix, its active bottom-nav item, and the drawer's selected-tab underline. In dark it brightens and keeps white text.
- **Indigo Deep** (`accent-hover`): primary hover. Darker in light, lighter in dark.
- **On Indigo** (`accent-text`): white in both themes.
- **Indigo Wash** (`accent-soft`): the Run pill inside each Run chip, the detected-platform download row, the 3px halo on a hovered Run chip and on focused fields and open buttons, the replica's selected row, active nav item, active chip and highlighted completion, and the hero's top glow.
- **Focus Indigo** (`focus`): the 2px keyboard outline on every focusable element, and the border of the open command bar.
- **Link Indigo** (`link`): text links, "more" links in section asides, the Run pill's label, and keyword colour in snippets. In dark it is the lightest indigo (#a7a2ff), used wherever indigo is text.

### Secondary (status triplets, inherited)

Each tone ships as text colour, soft fill, and border, used together. On the page: **Approved Green** (`success`) for "Dry run passed", the diff's added line, and check marks. **Rejected Red** (`danger`) for "critical" and "DROPPED" and the diff's removed line. **Needs Review Amber** (`warning`) for "Enforce" and "high". **Draft Grey** (`neutral`) for plain labels ("prod-us"). Inside the replica every tone appears as the app uses it, including **Release Violet** (`release`) for numbers in YAML; `info` keys YAML and info notices there.

### Tertiary (connection dots, v8s-only)

The app's cluster connection dots. They mark live connection state and never stand alone.

- **Connected Green** (`dot-ok`): a connected cluster; the replica's cluster tags and Streaming marker; the hero's release line.
- **Connecting Amber** (`dot-warn`), **Error Red** (`dot-err`), **Disconnected Grey** (`dot-idle`): defined to match the app. No state on the page uses them today.

Status counts in the replica's filter chips use 6px dots in the status tones (`success`, `warning`, `danger`, `info`, `neutral`), not the `--dot-*` family; those dots mean "rows in this state", not connection.

### Neutral (inherited from PixelCI)

- **Desk Grey** (`bg`): the page, the header at 82% with blur, the replica's sidebar and main area.
- **Card White** (`surface`): cards, buttons, Run chips, `section--inset` bands, the footer, the replica's top bar, table card, and overlays.
- **Inset Grey** (`surface-2`): hover fill, snippets and the diff body, problem-class chips, key caps.
- **Screenshot Mat** (`surface-3`): inline code; the Zyno band in dark.
- **Row Hover** (`surface-hover`): the replica's row and button hover.
- **Hairline** (`border`) and **Control Outline** (`border-strong`): containers, row and column dividers, the header's command button versus buttons, chips, and the phone frame.
- **Ink / Secondary Ink / Meta Grey** (`text`, `text-2`, `text-3`): headings and row names / ledes, row bodies, nav / captions, file names, icons in collection headings, column headers.

### Named Rules

**The One Indigo Rule.** Indigo means "this is the action, this is chosen, or this has focus". The header Download is the persistent primary; inside the page body only the hero download fills indigo. Section actions are Run chips, whose indigo is a wash, not a fill. Indigo never carries status, and it is not an emphasis colour for prose or headings.

**The Tag Triplet Rule** (inherited). A status tone is applied as soft fill, matching border, and tone text together, and every tag holds a word.

**The Dot Beside a Word Rule.** A connection dot is a 7px circle (6px in the replica) that always sits next to text naming the same thing: a cluster, "Streaming", a version line. Its colour must agree with that text.

## Typography

**Display Font:** Inter (with ui-sans-serif, system-ui, -apple-system, 'Segoe UI', Roboto, 'Helvetica Neue', sans-serif)
**Body Font:** Inter, the same stack.
**Label/Mono Font:** ui-monospace (with 'SF Mono', 'JetBrains Mono', Menlo, Consolas, monospace), the platform's monospace; not loaded.

**Character:** One sans-serif with Inter's single-storey a (`cv11`) and open digits (`ss01`), as in PixelCI. The site scales it up for a page: a tight, heavy display and a 16px body. Inter ships via Fontsource as static 400, 500, 600, and 700. Icons are Font Awesome Free (solid and brands) as an icon font.

### Hierarchy

- **Display** (650, fluid 40 to 68px, 1.02, -0.04em): the hero H1 only. The 404 uses a smaller variant (fluid 36 to 56px, 1.04).
- **Headline** (650, fluid 30 to 44px, 1.08, -0.03em): one per section, a plain sentence ("Fast because it sends less.").
- **Title** (650, fluid 20 to 24px, 1.25, -0.02em): sub-blocks that stand beside a section (trust, the phone block) and the Zyno band.
- **Card title** (600, 17px, 1.35, -0.01em): headings inside a collection card (Flux, Helm, the three run modes, the budget block).
- **Lede** (400, 19px, 17px at 600px and below, 1.55, Secondary Ink): the paragraph under a headline, about 60ch in the hero.
- **Body** (400, 16px, 1.55). **Body small** (400, 14px): row text, list items, footer links. **Caption** (400, 13px, Meta Grey): notes, hints, file names.
- **Control** (500, 14px, line-height 1): buttons, nav links, "more" links. Large buttons use 16px; the xl hero button is 17px at 600.
- **Tag** (500, 12px, line-height 1).
- **Column header** (600, 11px, uppercase, 0.045em, Meta Grey): the replica's table headers, sidebar sections, and fact labels; the download section's group headings.
- **Command** (mono 500, 13px): the command in a Run chip.
- **Mono** (400, 11 to 13px): snippets (13px; 12px in run columns), the diff (12.5px at 1.75), problem class chips (12px), download file names (11.5px), the replica's mono cells (12px), key caps (11px).

### Named Rules

**The Machine Text Rule** (inherited). Anything a machine reads or a person types is monospace: v8s commands, problem class names, CLI invocations, image and chart references, asset file names. Everything a person wrote is Inter, including version numbers and dates, which use tabular numerals.

**The Caps Are Column Headers Rule.** Uppercase 11px text exists only as the header of the table, list, or group directly beneath it, as the app draws its table headers. It never sits above a section heading as a label.

## Layout

A single centred column (max 1180px, 32px gutters, 16px at 600px and below) under a sticky 60px header. Sections pad 112px top and bottom (80px at 820px and below); tight sections pad 80px (56px). Sections alternate tone, never decoration: a hairline rule (`section--rule`) and a Card White inset band with hairlines top and bottom (`section--inset`).

The hero pads 72px top (40px at 640px) and 96px bottom. Its top row is the copy on the left and a 360px download card on the right, bottom-aligned, 64px apart; at 1000px the card drops under the copy (max 420px). Beneath, 48px down and spanning the column, sits the live replica, with a centred caption under it.

Every section below opens with a **section head row**: the heading and lede on the left (max 720px), and an aside on the right, bottom-aligned, holding the section's Run chips and "more" links, 48px above the body. At 900px the aside moves under the heading and runs horizontally. The body is one collection card, a split of checks and a picture, or both.

Collections are dense: problem families as 44px rows (200px name column, wrapped class chips), integrations as 52px rows (name, description, status tag), budgets as 36px spec rows, three run modes as columns divided by hairlines. Multi-column cards fold to one column at 900px; rows restack at 640px.

Breakpoints are max-width and component-local: 1000 (hero, budget, downloads, split with screenshot), 900 (header to burger, collection columns, section aside, trust, footer columns), 820 (section padding, 44px touch targets, footer links), 760 (the replica's phone layout, by container query on its own width), 640 (single-column grids, rows restack, the cluster screenshot hides, phone block stacks), 600 (gutter, lede), 560 (header CTA hides, footer two columns).

### Named Rules

**The Rows Not Cards Rule.** A set of like things is one card with hairline-divided rows or columns at the app's density, not a grid of separate airy cards.

**The App Gets the Width Rule.** The replica and screenshots span their column; no chrome or side rail takes horizontal space from a picture of the app.

## Elevation & Depth

Depth is tonal first, as in PixelCI: grey desk, white card, inset grey, hairline borders. The three PixelCI shadows keep their values in both themes, with one doctrine: pictures of the app are windows above the desk. The replica, the cluster screenshot frame, the phone screenshot, and the diff figure take the floating shadow, as do the replica's own overlays (command bar, drawer, cluster menu, shortcuts, bulk bar). The hero download card, the mobile menu, and the Zyno band take the attached shadow. Collection cards, buttons, Run chips, and fields take the resting shadow. The sticky header has no shadow: it is Desk Grey at 82% with `saturate(1.4) blur(12px)`, and its hairline appears only once the page has scrolled.

### Shadow Vocabulary

- **Resting** (`--shadow-sm`): collection cards, default and primary buttons, Run chips, the replica's fields and table card.
- **Attached** (`--shadow-md`): the hero download card, the mobile menu panel, the Zyno band, the replica's toast.
- **Floating** (`--shadow-lg`): the replica window and its overlays, screenshot frames, the diff figure.
- **Indigo halo** (`0 0 0 3px var(--accent-soft)`): a hovered Run chip, a focused field, an open button, the open command bar (paired with the floating shadow).

### Named Rules

**The Window Floats Rule.** Only a picture of the app lifts to the floating shadow. The download card is the one site card raised to attached, because it is the page's one destination. Hover changes border, fill, or halo, never elevation.

## Shapes

PixelCI's nested radii: 12px containers, 8px controls, 5px inner pieces (tags, nav links, Run pills, class chips, download-way links). Borders are 1px: Hairline for containers and dividers, Control Outline for pressable things. Key caps are 4px with a 2px bottom edge. The phone screenshot sits in a 36px-radius frame with a Control Outline border; the brand mark is its own rounded tile. Dots are full circles. In the pipeline card, the hand-off between stages is a 10px chevron drawn from two Control Outline edges, sitting on the column hairline (rotated onto the row hairline when stacked). Focus is a 2px Focus Indigo outline offset 2px; inside the replica's clipping containers it draws inside the edge.

## Components

Controls are bordered and even. They change colour over 120ms and keep the product's proportions, scaled up a step for a page.

### Buttons

- **Shape:** 8px radius, 36px tall, 14px padding, 8px icon gap, resting shadow.
- **Default:** Card White, Control Outline, Ink. Hover fills Inset Grey.
- **Primary:** Indigo fill and border with white text. Hover moves to Indigo Deep.
- **Ghost:** transparent, no border or shadow, Secondary Ink; hover darkens to Ink. GitHub in the header and the 404.
- **Sizes:** large (46px, 20px padding, 16px label) for the 404, mobile menu, and Zyno band; xl (52px, 22px padding, 17px semibold, 10px radius) for the hero download only; download rows use a 32px default button.
- **Disabled:** 55% opacity, not-allowed cursor.
- **Touch:** at 820px and below every button outside a product picture is at least 44px tall.

### Run chip (signature)

A real v8s command that runs in the hero replica. ## Do's and Don'ts

### Do:

- **Do** take every colour from the custom properties in `tokens.css`, keeping PixelCI's names and values for everything except the accent family and the dots.
- **Do** keep indigo to action, selection, and focus; the section-level action is a Run chip, not a filled button (The One Indigo Rule).
- **Do** give every section with a real, demo-able v8s command a Run chip in its heading row, and put "more" links there otherwise.
- **Do** show status as a tag triplet with a word in it, and connection state as a dot beside a word whose meaning it matches (The Dot Beside a Word Rule).
- **Do** pack collections as hairline-divided rows or columns inside one card (The Rows Not Cards Rule).
- **Do** set commands, class names, CLI lines, and file names in monospace, and everything else in Inter (The Machine Text Rule).
- **Do** use the app's own light and dark renders as a pair, so a screenshot always matches the page theme.
- **Do** nest radii 12px, 8px, 5px from container to control to inner piece.
- **Do** keep motion to 120ms colour changes, the header hairline (160ms), and the replica's one-time typed command; under reduced motion the command bar is a still.

### Don't:

- **Don't** use another product's accent; v8s is indigo.
- **Don't** use indigo for status, emphasis, or decoration, or a status tone for a general-purpose button.
- **Don't** put a Run chip on a command v8s doesn't have.
- **Don't** put an eyebrow, kicker, or command label above a heading; uppercase caps only head the list beneath them (The Caps Are Column Headers Rule).
- **Don't** spread a collection across separate feature cards with icons.
- **Don't** lift site cards past the resting shadow, except the hero download card; floating shadows belong to pictures of the app (The Window Floats Rule).
- **Don't** use the desk grid and glow anywhere but the hero and the 404.
- **Don't** hard-code a colour, radius, or shadow where a token exists.
- **Don't** copy the known gaps below into new work.

### Known gaps, not rules to copy

- **Indigo as emphasis.** The hero H1's "No lag." is set in `accent` (`link` in dark). That is indigo used as a highlight colour, outside action, selection, and focus.
- **Dot that ignores state.** The hero release line's dot is always `dot-ok` green, including when the GitHub check fails and the text says "Couldn't reach GitHub just now".
- **Two indigo fills in the first viewport.** The header Download and the hero download are both filled at 1440x900.
- **Weight 650 is not loaded.** Headings, the replica's title, and the Zyno heading ask for 650; only static 400 to 700 ship, so they render at 700.
- **Literal colours in the Zyno band.** `#0c0d10`, `#ececf0`, `#fff`, `#aeb2bd`, `#15171c`, `#eceef2`, and Zyno's `#2855d4` are literals, not tokens.
- **Carried but unused primitives.** `site.css` came over from the sales site with things this page does not use: `.card` and its variants, `feature-icon`, the comparison table and its stacked form, form fields, `grid-2/3/4`, `section-head`, scroll `reveal`, `notice`, the `info`, `release`, and `accent` tag tones, the `data-when` release gates, and `--cmdbar-h`. Their presence is not evidence of a v8s pattern.
- **Off-scale values.** Radii of 10px (xl button), 36px (phone frame), 4px (key caps, inline code, the replica's tags), and 2px (Zyno square) sit beside the three radius tokens; mono runs at 10, 11, 11.5, 12, 12.5, and 13px.
- **Local code-chip overrides.** The download ways, download headings, and 404 code each undo the global inline-code chip locally.
